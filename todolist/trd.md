# Todo List 웹사이트 TRD

## 1. 기술 구성

- **구조:** 정적 웹 페이지
- **마크업:** HTML5
- **스타일:** CSS3
- **동작:** Vanilla JavaScript (ES6+)
- **저장소:** 브라우저 `localStorage`
- **서버/API/빌드 도구:** MVP에서는 사용하지 않음

## 2. 디렉터리 및 파일 구성

```text
todolist/
├── index.html
├── css/
│   └── style.css
└── js/
    └── app.js
```

문서 파일(`prd.md`, `trd.md`, `task.md`)은 프로젝트 루트에 둔다. 실제 구현 시 위 애플리케이션 파일을 추가한다.

## 3. 애플리케이션 설계

### 데이터 모델

할 일은 다음 필드를 갖는 객체로 표현한다.

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | 문자열 | 항목을 구분하는 고유 식별자 |
| `title` | 문자열 | 앞뒤 공백을 제거한 할 일 제목 |
| `completed` | 불리언 | 완료 여부 |
| `createdAt` | 문자열(ISO 8601) | 생성 시각 |

저장 키는 `todolist.tasks`를 사용하고, 값은 위 객체의 배열을 JSON으로 직렬화한다. 필터 선택은 MVP에서 영구 저장하지 않는다.

### 상태 및 렌더링

- JavaScript에서 목록과 현재 필터 상태를 관리한다.
- 목록 변경 시 저장소를 갱신하고 화면을 다시 렌더링한다.
- 화면에 사용자 입력을 반영할 때는 텍스트로 삽입하고 HTML로 해석하지 않는다.
- 완료 여부에 따라 전체/미완료/완료 필터 결과를 계산한다.

### 저장 및 오류 처리

- 초기화 시 저장 데이터를 읽고 JSON 파싱 및 데이터 구조를 확인한다.
- 저장 데이터가 없으면 빈 배열을 사용한다.
- 저장 데이터가 손상되었거나 접근할 수 없는 경우를 사용자에게 알리고, 임의로 정상 저장에 성공한 것처럼 처리하지 않는다.
- `localStorage` 저장 용량 또는 접근 오류가 발생하면 상태가 브라우저에 저장되지 않았음을 사용자에게 표시한다.

## 4. 화면 및 접근성

- 시맨틱 HTML 요소와 명시적인 입력 라벨을 사용한다.
- 버튼은 목적을 명확히 표현하고 키보드 포커스가 보이도록 한다.
- 수정 상태 진입/저장/취소가 키보드로 가능하도록 구성한다.
- 삭제 컨트롤은 대상 항목을 알아볼 수 있도록 접근 가능한 이름을 제공한다.
- CSS는 작은 화면을 기본으로 작성하고 필요한 지점에서 반응형 레이아웃을 확장한다.
- 완료 상태는 취소선이나 색상만이 아니라 체크 상태 등으로도 전달한다.

## 5. 브라우저 및 실행

- 최신 안정 버전의 Chrome, Edge, Firefox, Safari를 대상으로 한다.
- `index.html`을 브라우저에서 열어 사용할 수 있도록 외부 라이브러리 및 서버 의존성을 두지 않는다.
- 실제 브라우저 검증 시 `localStorage` 사용을 위해 로컬 정적 서버 환경에서도 확인한다.

## 6. 검증 전략

- 기능 확인: 추가, 공백 입력, 완료 토글, 수정, 취소, 삭제, 필터, 빈 상태
- 영속성 확인: 변경 후 새로고침 및 브라우저 재방문
- 오류 확인: 손상된 저장 데이터 및 저장소 사용 불가 상황
- 반응형 확인: 좁은 모바일 화면과 데스크톱 화면
- 접근성 확인: 키보드만으로 핵심 흐름 수행, 포커스 및 입력 라벨 확인
